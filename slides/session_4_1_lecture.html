Lesson explanationSession 4.1

Learn

Separate fixed instructions from changing notes

  • A reusable prompt keeps the same task directions while a placeholder such as {Meeting_Notes} marks the content that changes each week. The user replaces the placeholder with new notes; the prompt's role and output rules remain stable. This reduces repeated setup but does not guarantee a correct summary.
Learn

Design an output that prevents invented details

  • Specify the sections the team needs, such as Decisions, Actions, and Open Questions. For actions, request a task, owner, and due date. Tell the model to write "Not stated" if the notes do not name an owner or date. This makes a missing field visible instead of inviting a guess.

Test reuse against the source

  • With the supplied notes, Jamie owns the draft and Priya reviews it; legal review has no named owner. Compare every name, date, decision, and action in the result with the notes. Then try a second short set of notes without changing the fixed instructions. A reusable prompt is ready only when it works on a fresh input and its limits are clear.
Apply

Three-step method

  • Define the repeated task and audience; add named input placeholders and output fields; test the template and compare its claims with the input.
